# apps/web — the site

Vercel's [TanStack Start template](https://github.com/vercel/vercel/tree/main/examples/tanstack-start)
(Apache-2.0) on TanStack Start 1.169, running on Cloudflare Workers + Static
Assets through [`@cloudflare/vite-plugin`](https://developers.cloudflare.com/workers/vite-plugin/),
TanStack Start's own Cloudflare target:

- `/` — the welcome page, rendered by the Worker
- `/demo/start/server-funcs` — a todo list read by a GET server function in
  the route's loader and added to by a POST one, the visitor's list kept in
  their own httpOnly cookie (`src/data/todos.ts`: JSON, capped to stay under
  4 KB)
- `/demo/start/api-request` — a page whose browser fetches the API route,
  `GET /demo/api/names` (`src/routes/demo/api.names.ts`)
- `/demo/start/ssr/full-ssr`, `/data-only` and `/spa-mode` — the same server
  function rendered three ways

The site's name — every page's `<title>` — is in `src/lib/site.ts`.

```bash
pnpm dev        # vite dev on http://localhost:3000 (the server runs in workerd)
pnpm build      # vite build → dist/server (the Worker) + dist/client (Static Assets)
pnpm preview    # wrangler dev over the built Worker
pnpm test       # vitest
```

How it is deployed — per environment, on merge to `main` — is the
repository's README and `component.yaml` beside this file.
